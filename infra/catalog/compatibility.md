The Keycloak operator 26.8.2 is cataloged, behind `platform-portal` (off in `local` and `managed-example`), as the local chart `infra/charts/keycloak-operator` (component `keycloak-operator`, namespace `keycloak`, core phase). A manifest component cannot carry a feature flag, so the chart vendors upstream's files, and `managed-example` overlays the two image values with mirror references at the same digests; the approved-images entries are `keycloak-operator` and `keycloak-server`. Source: `https://raw.githubusercontent.com/keycloak/keycloak-k8s-resources/26.8.2/kubernetes/` followed by the file name; sha256 of each upstream file at 26.8.2: `kubernetes.yml` `e1da7dd96a3f4bcea806ad67f13b695fc813d5f37257266bc037dcb21321e6e5`; `keycloaks.k8s.keycloak.org-v1.yml` `20c51247cb6cbc6158098caabeaf6b429dc8c016e35829f5ddd9c468b7582667`; `keycloakrealmimports.k8s.keycloak.org-v1.yml` `8d552e1864d78117a07e535479ddb36e16a42b2695726c875f44828e1323edd4`; `keycloaksamlclients.k8s.keycloak.org-v1.yml` `7c69d146f610f3c40acf4466518e89615b6fce7ee2a03d75cd93b7a9a7bf259e`; `keycloakoidcclients.k8s.keycloak.org-v1.yml` `15d9199822d1918438bd1d093eee3ec8406e7f9d0837c4527fd6da99c63b058a`. All four CRDs are vendored (the operator has a controller for each, and upstream 26.8.2 ships all four; about 950 KB, in `templates/` so upgrades apply them) as `templates/crd-keycloaks.yaml`, `crd-keycloakrealmimports.yaml`, `crd-keycloaksamlclients.yaml` and `crd-keycloakoidcclients.yaml`. Differences from upstream, and no others: `crd-keycloakrealmimports.yaml`, `crd-keycloaksamlclients.yaml` and `crd-keycloakoidcclients.yaml` are byte-identical to upstream. `crd-keycloaks.yaml` differs in two description lines (136 and 5134) that gave the default JDBC URL as a literal URL and now say it in words, because TruffleHog's JDBC detector reports the literal as an unverified secret; the schema is untouched. `templates/operator.yaml` is `kubernetes.yml` with the `ClusterRole` `keycloak-operator-clusterrole` and its `ClusterRoleBinding` removed, a namespace of the release added to every namespaced resource and RoleBinding subject, and three image values (the operator `image`, and the `kc.operator.keycloak.image` and `RELATED_IMAGE_KEYCLOAK` environment values) taken from `.Values.operator.image` and `.Values.keycloak.image`. The removed role granted only `get` on `ingresses` in `config.openshift.io`, an OpenShift API that the platform's clusters do not serve, so the operator holds no cluster-scoped read it does not need; the live run shows whether the operator starts without it. Helm creates the `keycloak` namespace. Owed to the live run: that the CRDs fit a Helm release at about 950 KB, that the operator starts under Gatekeeper admission with the digests, and that it creates a Keycloak from the pinned server image.

The platform Keycloak (ADR 0113, plan 15 Step 6 slice a) is cataloged, behind `platform-portal` (off), as the local chart `infra/charts/platform-keycloak` (component `kore-platform-keycloak`, namespace `keycloak`, configuration phase, after `keycloak-operator` and `kore-postgresql-api`). It renders a `PostgreSQLInstance` claim `keycloak-db` (Retain, standard class, 2Gi, PostgreSQL 17) and a `Keycloak` `keycloak` (`k8s.keycloak.org/v2beta1`, the CRD's storage version) with one instance, no image of its own (the operator starts its pinned server digest), the database read from the claim's `keycloak-db-rw` Service and `keycloak-db-app` Secret by reference, the bootstrap admin from the `keycloak-admin` Secret, host `keycloak.<platformDomain>` and ingress off until the portal's route exists. `kore platform up` streams `keycloak/keycloak-admin` (`kubernetes.io/basic-auth`, user `kore-admin`, 192 random bits) through kubectl's stdin right after the operator installs, and never rotates an existing one (ADR 0034). The recovery objective `keycloak-data` covers the database by `kore data export --environment local --namespace keycloak`. Owed to the live run: that the claim's Cluster and Secret appear in the `keycloak` namespace under Gatekeeper admission, that Keycloak reaches ready against the claimed database (the connection uses the driver's default `sslmode`, which prefers TLS, where the claim's Secret says `require`), that the audit-mode `KoreSecrets` constraint reports the streamed Secret (a policy allowance is a later, deliberate change), and that `kore data export` and the restore work for that namespace. Still not delivered: the Crossplane Keycloak provider install and its `ProviderConfig` (slice b), and the realm and the `platform-operators` group owned by the Organization API (slice c).
